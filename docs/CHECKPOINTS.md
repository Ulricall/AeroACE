## AeroACE dictionary contents

The configured maximum is 10,000 entries, but the supplied files contain:

| File | Stored entries | Key/value shapes |
|---|---:|---|
| `aeroace_trained.pt` | 4,000 | `(4000, 33)` / `(4000, 99)` |
| `aeroace_trained_aeroace_fixed_gate.pt` | 4,000 | `(4000, 33)` / `(4000, 99)` |
| `aeroace_trained_aeroace_vanilla_gru.pt` | 111 | `(111, 33)` / `(111, 99)` |
| `neuralbem.pt` | 4,000 | `(4000, 33)` / `(4000, 99)` |

The main manuscript states that experiments use `E=10000`. A maximum capacity
of 10,000 is not evidence that 10,000 entries were actually stored. The main
AeroACE checkpoint contains 4,000 entries, and the vanilla-GRU dictionary has
only 111; therefore the supplied fixed-gate/GRU checkpoints do not provide a
matched dictionary-size ablation.

## Missing provenance

The checkpoint payloads do not include:

- source revision or commit hash;
- training and validation seed lists;
- training trajectory/wind manifest;
- tuning trial identifier or the reported 50-trial search ledger;
- optimizer/scheduler history sufficient to resume the reported training;
- the manuscript table/row generated by the file;
- package versions or hardware;
- creation time independent of filesystem metadata.

The model tensors are stored in float64. The final manuscript reports an
approximately 5.0 MB float32 dictionary configuration; the provided checkpoint
payloads do not document a conversion step or the exact deployment artifact.

## Methods without supplied checkpoints

PID, OMAC, Neural-Fly, OoD-Control, and the source implementation labelled
Decision Transformer have no released learned checkpoints. In the current
`contrast` path, `run.py` trains OMAC, OoD-Control, and the Transformer path
before testing, but tests Neural-Fly without first calling `train()`. RTN-MPC and
MLMPC also have no pretrained artifact in the source tree; they initialize their
learned components locally and adapt online.

PyTorch checkpoint files use pickle-based serialization. Load only files from a
trusted source.
